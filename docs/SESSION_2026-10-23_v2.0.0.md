## What changed and why

### 1. Download speed (`src/hrrr_wind/cache.py`)
Compared our method with `../hrrr-data-retrieval`. Both use FastHerbie with byte-range subsetting, so the download itself was already near its floor. The slack was elsewhere:
- `fetch_wind` now decodes each hour in a thread pool and crops it to each venue's box immediately, instead of concatenating full-CONUS (1059x1799) grids for a whole 72-hour chunk. New signature: `fetch_wind(dates, source, slices, max_threads=50)` returning `(valid_times, {venue: (u, v)})`; `fetch_with_retry` also takes `slices`.
- `build_cache` fetches the next chunk on a worker thread while the previous one is stored.
- Verified identical output to the old method on 12 real hours. The user reported it "helped a bit"; no full multi-year timing was done.
- Not done: wgrib2 `-small_grib` cropping, parallel alternate-source retries, the NOAA Zarr archive.

### 2. Web UI layout
- **Study tabs:** a tab per study across the top plus a `+` tab for a new study; extra studies wrap to another row. The home page was removed; `#/` opens the first study (or the new-study page if there are none). A lock icon marks the locked reference study, and a dot flags studies needing attention.
- **Inputs tab (formerly Venues), now first:** a Years section (the year picker, always shown, read-only for locked studies) above a Venues section. The header's "Edit years" link is gone and Rename is a pencil icon.
- **Compare tab removed:** its tables sit under a "Comparison" heading at the bottom of Overview. Old `#/s/<id>/venues` and `/compare` links still work (`MOVED` map in `app.js`).
- Studies open on Overview when their tab is clicked.

### 3. Sweet spot 5-15 kt to 5-20 kt (BREAKING, hence 2.0.0)
- Stats, usable days, validation bins, the single-club CLI and the UI all use 5-20 kt; "strong" is now >= 20 kt.
- Output columns renamed: `pct_5_15` -> `pct_5_20`, `pct_ge15` -> `pct_ge20` (also `_lo`/`_hi`, `obs_`/`hrrr_`, per-year, paired, sensitivity). `pct_15_20` removed. `pct_5_to_15kt`/`pct_over_15kt` in `climatology.py` became `pct_5_to_20kt`/`pct_over_20kt`.
- Colors: blue below 5 kt, three greens for 5-10/10-15/15-20, amber for 20+ (web CSS `--r1..--r5`, `build_slide.py`, `build_report.py`, matplotlib summary figure).
- Results written before the change are detected as out of date (`is_stale` in `api/app.py` checks for the `pct_5_20` column), so other studies get the usual recompute prompt.
- The GTYC/HYC reference study's CSVs, figures and HTML report were regenerated. **Its conclusion changed:** HYC minus GTYC sweet-spot share is +11.8 points (CI +4.6 to +20.1), distinguishable from zero; under 5-15 kt it was not. HRRR has almost no hours >= 20 kt, so the old "HYC fails on heavy air" story went away. The hand-written report text was rewritten and `build_report.py` now asserts that the CI excludes 0.
- Still stale on purpose: `studies/gtyc_hyc_2028/outputs/Venue_Wind_Analysis_GTYC_HYC.md` (hand-written, 5-15 kt), `NOTES.md` history (a banner explains), and the published claude.ai artifact linked in NOTES.md.

### 4. Data caching (option A only)
Re-evaluated the cache layout. Findings: the `cache_<venue>_<tag>.npz` tag names (year range, venue suffix) are only filenames, since the real years are read from inside each file; `more_caches` and pending-tag logic are a second layer tracking the same thing; checkpoints duplicated the finished caches; and venues never share downloads (about 40-60 min per venue for 2015-2026 on Lake St. Clair, even for clubs within 7 nm whose 18 nm boxes overlap about 80%).

Decision: do **A** (small cleanup) only. The user doubts that nearby-club comparisons will be a real use case, so sharing a regional cache (option C) and per-year files without tags (option B) were not pursued.
- `build_cache` deletes `ckpt_<tag>` once the caches and `missing_<tag>.json` are written. Interrupted runs keep checkpoints and resume.
- Rerunning a finished tag is a no-op (never refetches or overwrites).
- Cache tags are no longer shown in the Files page, the advanced download table (years instead) or job labels. The manual download form still asks for a tag.
- The 13 leftover `ckpt_*` folders (17 MB) in the Lake St. Clair study were deleted by hand.

### 5. Smaller items
- Static files are served with `Cache-Control: no-cache` (`RevalidatedStaticFiles` in `api/app.py`). Cause: after the palette change a browser mixed old JS with new CSS and showed green for "< 5 kt". A hard reload fixes an already-stale browser.
- Job logs: `prune_logs` in `jobs.py` keeps the newest 3 `.log` files per study's `jobs/` folder (`LOG_KEEP = 3`).
- A bug introduced mid-session and fixed in the same push set: the advanced downloads table used `yearRanges` without importing it, which crashed the Inputs/Venues page on non-read-only servers. It was in `7e33221` and fixed in `b03fccf`.
